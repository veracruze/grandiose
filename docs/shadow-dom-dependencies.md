## F. Fragile CSS techniques

- **Stacked-ID specificity** (`#sidebar-container#sidebar-container#...`, `#main-window#main-window`, `#tabbrowser-tabs#tabbrowser-tabs`) in 12/13/14/17. Any new competing rule needs the same count. In 12, `#browser:not(:has(#tabbrowser-tabbox[...]))` counts as **two** IDs (`#browser` plus the ID inside `:has()`), so those selectors have 5 IDs against section 7's 4. So a CSS slide rule can out-rank the JS engine's rules and both could move the rail; the 12 section 2 slide rules therefore stand down while `[uc-push-overlay]` is set.
- **Firefox inline styles beaten by `!important`**: `--sidebar-launcher-collapsed-width` on `#browser`, margins/min/max-width on `#tabbrowser-tabbox` (13).
- **Web animations pinned**: `translate` and `transform` set to `none` on `#tabbrowser-tabbox` outside fullscreen/expand-on-hover (13); view-transition names disabled (E2). Anything Firefox moves to a new animation property is not covered.
- **`:has()`**: no `:root:has()` selector remains. What is left is scoped to an element: `#urlbar:has(#identity-box...)`, `#urlbar-container:has(...)` (03), `#navigator-toolbox:has(#notifications-toolbar ...)` (02), `#browser:not(:has(#tabbrowser-tabbox[sidebar-launcher-hovered]))` (12), `#browser:has(#sidebar-container[hidden][sidebar-panel-open])` (06), `.buttons-wrapper:has(> .overflow-button)` (07, inside the shadow root), `tab-group:has(> .tabbrowser-tab[selected])` (15), the back/forward `:has(+ ...)` margins (04), `.toolbarbutton:has(> .toolbarbutton-badge-stack)` (05), `.widget-wrapper:has(> .clocks-widget)` and the `.modalOverlayOuter:has(.topsite-form)` rules (userContent).
- **Other CSS features**: anchor positioning in 09 (`anchor-name`, `position-anchor`, `anchor()`; has a fallback) **and** in 03 (`anchor-scope`, `anchor-name: --uc-dd-fav`, `position-anchor`, `anchor(start)` for the dropdown badges; only inside `@supports (position-anchor: --a)`, no fallback layout), `abs()` (17, Firefox 118+), container queries (`container-type: inline-size`, `100cqw` in 04/06), `linear-gradient(in oklab ...)`, `color-mix()`, individual `translate` / `scale` properties, `transition-behavior: allow-discrete` (04), `-moz-toolbar-prefers-color-scheme`, `content-visibility`, `-moz-element(#statuspanel)` (03), `@-moz-document` on `chrome://`, `about:blank` and `about:newtab` URLs (userContent.css), `mask` shorthand with `url(data:)` icons (05, 15).
- **Theme-relative assets**: `../thinking-dots.svg` (04), `../fonts/*.ttf` and `../Nunito-Black.ttf` (00). A missing file fails silently (throbber disappears, fonts fall back). about:newtab needs Poppins installed system-wide (J).
- **Transparent window frame (17)**: `--tabpanel-background-color: transparent`, and `#main-window`, `#browser`, `#tabbrowser-tabpanels` set to `transparent` **always** (not only with an image). It relies on the OS window backdrop (DWMBlurGlass plus the Windows transparency setting, see the README) and on `browser.tabs.allow_transparent_browser` (user.js). The background image is a `#main-window::before` layer at `z-index: -1`, offset by `--uc-bg-x` / `--uc-bg-y`, painted at `opacity: var(--uc-bg-image-opacity, 0.5)`.
- **`#sidebar-main` has no id** (confirmed in the Browser Console: `getElementById` is null, `querySelector("sidebar-main")` has `id=""` and parent `#sidebar-container`). Selectors that list it next to `sidebar-main` are harmless. Scripts must not use `getElementById("sidebar-main")` (sidebarPushSettle did until 2026-11-17).
- **Stylesheet order**: 17, 18 and 19 are imported after 16. Anything that must override 16 (or that 16 cannot override, because the rule is `!important`) lives in the later file: 17's PiP control fade has its own reduced-motion switch-off.
- **Global user content rules** (userContent.css, outside any `@-moz-document`): the scrollbar colours (`* { scrollbar-color }`, dark by default, light under `@media (prefers-color-scheme: light)`, so they follow the page's scheme), the `xul|scrollcorner, xul|resizer, xul|scrollbar` and `#flash_scroller` / `.category-bar` / `.category-list` `color-scheme: dark` rules, and the `#buttons-container ...` Screenshots / mini-window toolbar styling. The `@namespace xul` line must stay at the very top of the file (it was invalid after style rules until 2026-11-17). A copy uploaded earlier on 2026-11-21 had these rules removed; they are back in the current file (Changelog).
- **PiP / screenshots styling** (userContent.css, 17): `@-moz-document url-prefix("about:blank")` (transparent `html, body` and `#playervideo`), `#buttons-container .buttons-wrapper`, `.screenshots-button`, `#pop`; the control fade `html[windowtype="Toolkit:PictureInPicture"] #controls-bottom, #close, #unpip` is in 17.
- **Locale**: the labels that C6 and C12 add are localized from `Services.locale` at load (17 languages, English fallback). A locale outside the list gets English. 05 and the scripts otherwise match on ids or l10n ids, not label text.
- **`--uc-active-collapsed`** (first rule of 01) aliases `--uc-rail-collapsed`; 07 section 18 rule 1 and its pre-rule are invalid without it.

## I. Monkey-patches and load-order dependencies

| Patched member | Patched by | Notes |
|---|---|---|
| `SidebarController.onMouseEnter` | railExpandTargets, then sidebarContextMenuHold (wraps whatever is there) | Load order decides which wrapper is outermost. contextMenuHold's own header says its re-check calls `_reconcileHoverState()`, which bypasses railExpandTargets' veto, and it avoids that on purpose after Customize closes |
| `SidebarController.onMouseLeave`, `debouncedMouseEnter`, `_collapseLauncher`, `_isMenuPopupOpen` | sidebarContextMenuHold | Guarded by `hasFn()`; one warning if a member is gone |
| `FullScreen.getMouseTargetRect` | fullscreenRailHover | Falls back to the original rect inside a `try` |
| `document.startViewTransition` | sidebarRailHold | Marker `document.__ucVtReleaseHook` prevents double wrapping |
| `HTMLInputElement.value` on `gURLBar.inputField` | urlHostHighlight | Instance-level `defineProperty`; any Firefox code that replaces the input element loses it |
| `Element.prototype.attachShadow` (chrome window at load, panel window at `DOMWindowCreated`) | sidebarCloseLeft | Only sees roots created afterwards; `dispose()` removes the inline styles but does not restore the prototype |
| `FullScreen._isPopupOpen` (set, not wrapped) | sidebarOverflowFit | Cleared by Firefox's own `popuphidden` handler |
| Default-branch pref `layout.css.prefers-color-scheme.content-override` = 3 | SidebarToggles | A user value (set from the panel) wins over it |
| `gBrowser.setIcon` | FaviconUpgrader (C30) | Only FaviconUpgrader wraps it. extensionIcons (C12) just CALLS it with a `data:` PNG for `moz-extension://` tabs; FaviconUpgrader's `pageOf()` returns null for those (it handles http / https only), so that call goes straight through to Firefox. Load order does not matter. FaviconUpgrader shows its own icons through the `origSetIcon` it captured at start |
| `PlacesUtils.favicons` (property replaced with a Proxy) | FaviconUpgrader (C31) | Only one patcher is known, and each window layers on the original service, never on another window's proxy. Check that the property is still writable / configurable (`PlacesUtils.favicons` must be the proxy after start, the script warns otherwise) and that `LinkHandlerParent` still goes through that property. Another script or extension that also replaces it would sit in the same call path |

Each script has a `window.__uc*` or `sc.__uc*` guard so a second load does nothing; if you reload scripts without restarting, clear the guards or restart. sidebarCloseLeft is the exception: it versions its guard and disposes the older instance.
